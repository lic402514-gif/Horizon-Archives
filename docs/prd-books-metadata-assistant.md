## 1. 执行摘要

本项目旨在开发一款面向中小型图书馆（藏书数千至数万册）的**离线桌面软件**——图书元数据录入助手。用户扫描图书 PDF 后，工具通过 OCR + LLM 自动提取版权页元数据，辅以中图分类号智能推荐，最终生成结构化 JSON/MARC 并自动重命名源文件。

产品定位为**图书馆编目辅助工具**，目标用户为图书馆编目员或扫描档案员。

### 技术路线

| 方案 | 优点 | 缺点 |
|---|---|---|
| Electron/WebView + 云端 LLM | 原生体验、易打包 | 体积大、依赖网络 |
| PyWebview + 云端 LLM | 轻量、Python 全栈 | 跨平台兼容性略差 |
| 本地大模型完全离线 | 数据安全、无网络需求 | 需强 GPU、部署难 |

**推荐**: PyWebview + FastAPI 后端，云端 LLM 为主、本地小模型兜底。安装包可离线安装，但核心元数据抽取依赖网络 API；OCR 环节（PaddleOCR）完全离线可用。

---

## 2. 产品定位与目标用户

- **定位**: 辅助图书馆自动从扫描件抽取书目元数据，整合 OCR、AI 模型和人机交互，提升编目效率。
- **目标用户**: 中小型图书馆编目员 / 数字化人员。有一定编目基础（了解 MARC/RDA），无需编程技能。
- **使用场景**: 纸质书扫描为 PDF/图像 → 工具自动 OCR + 提取 → 人工校对 → 导出 + 文件自动重命名。

---

## 3. 工作流

```
上传PDF ─→ OCR(前10页) ─→ 版权页识别 ─→ LLM抽取元数据 ─→ CLC分类号推荐 ─→ 人工校对
                                                                              │
                                                              ┌───────────────┘
                                                              ▼
                                                   确认元数据 ─→ 自动重命名文件
                                                              ─→ 导出 JSON/MARC
```

### 详细步骤

1. **上传文档** — 单本或批量上传 PDF/图像
2. **OCR 识别** — PaddleOCR 对前 5–10 页提取文本
3. **版权页识别** — 关键词打分 + 位置先验 + LLM 辅助，确定版权页
4. **LLM 抽取元数据** — 将版权页文本输入 LLM，输出结构化 JSON
5. **CLC 分类号推荐**（见 §5） — 根据书名/作者/ISBN 联网搜索推荐
6. **人工校对** — 表单对照 OCR 原文，修改确认
7. **自动重命名**（见 §6） — 按规范格式重命名源文件
8. **导出** — JSON / CSV / MARC，导入馆藏系统

🔴 = v1.1 新增字段

### 字段说明

- **`doc_type`**: GB/T 7714 文献类型标识。常见值：`M`（专著）、`J`（期刊）、`D`（学位论文）、`C`（会议录）、`N`（报纸）、`P`（专利）。LLM 根据书名和内容推断；无法确定时默认 `M`。
- **`clc`**: 中国图书馆分类号。由 CLC 智能推荐功能填充（见 §5），用户确认后写入。

## 5. CLC 分类号智能推荐 🔴

### 问题

编目员通常不知道一本书的精确 CLC 分类号（如 `A123`），只能凭经验猜测大类。误分类会导致图书在馆藏系统中无法被正确检索。

### 方案

用户输入书名/作者/ISBN 后，系统调用 **DeepSeek 联网搜索 API**，检索以下来源的 CLC 数据：

- 中国国家图书馆 OPAC
- 各省级/高校图书馆书目系统
- 豆瓣读书、当当等图书电商平台
- CIP（图书在版编目）数据

返回结构化推荐列表：

```json
[
  {
    "clc": "A123",
    "clc_name": "马克思恩格斯著作",
    "source": "国家图书馆, 上海图书馆",
    "confidence": 0.95,
    "notes": "多馆一致"
  },
  {
    "clc": "A12",
    "clc_name": "单行著作",
    "source": "北京大学图书馆",
    "confidence": 0.72
  }
]
```

### 交互

```
┌─────────────────────────────────────────────┐
│ 分类号: [________] 🔍 智能搜索               │
│                                              │
│ ┌─── 推荐分类号 ─────────────────────────┐  │
│ │ ● A123  马克思恩格斯著作                   │  │
│ │   📚 国家图书馆, 上海图书馆  ████ 95%    │  │
│ │ ○ A12   单行著作                          │  │
│ │   📚 北京大学图书馆          ███ 72%     │  │
│ │ ○ 手动输入其他分类号...                    │  │
│ └──────────────────────────────────────────┘  │
└─────────────────────────────────────────────┘
```

用戶点击某一项即填入 `clc` 字段。支持降级策略：

| 优先级 | 策略 | 触发条件 |
|---|---|---|
| 1 | ISBN 缓存命中 | 同一 ISBN 24h 内已搜索过 |
| 2 | DeepSeek 联网搜索 | 网络可用 |
| 3 | LLM 纯推理（无来源） | 网络不可用 |
| 4 | 手动输入 | 全部失败 |

### 成本

DeepSeek `deepseek-chat` 联网搜索约 ¥0.005–0.02/次。处理 1000 本书约 ¥5–20。

## 6. 自动文件重命名 🔴

### 问题

扫描件通常以 `scan001.pdf`、`IMG_20250101.jpg` 等无意义名称存在。编目完成后手动重命名效率极低且易出错。

### 格式规范

```
作者_作品名[文献类型]_译者_出版社_年份(版次)
```

**示例**:

```
马克思_资本论[M]_中共中央编译局_人民出版社_2004(2).pdf
曹雪芹_红楼梦[M]_人民文学出版社_1982(1).pdf
```

> **注：译者字段为空的则跳过。**

### 组件映射

| 文件名组件 | JSON 字段 | 缺失时 |
|---|---|---|
| 作者 | `authors[0]` | `未知` |
| 作品名 | `title` | `未知书名` |
| [类型] | `doc_type` | `[M]` |
| 译者 | `translators[0]` | 省略整段 `_译者` |
| 出版社 | `publisher` | `未知出版社` |
| 年份 | `pub_year` | `未知年份` |
| (版次) | `edition` → 提取数字 | 省略括号 |

### 去重策略

同名文件加数字后缀：`_2`, `_3`，或附加原文件名 6 位短哈希。

### 安全处理

- 过滤 Windows 禁止字符：`\ / : * ? " < > |` → 替换为全角或下划线
- 截断超长文件名（256 字符限制，给路径留余量）
- 仅重命名输出副本，**不动原始扫描件**

### 交互

```
┌─────────────────────────────────────────────┐
│ ✅ 元数据已确认                              │
│                                              │
│ 📄 建议文件名：                               │
│ ┌─────────────────────────────────────────┐  │
│ │ 马克思_资本论[M]_中共中央编译局_人民出版 │  │
│ │ 社_2004(2).pdf                          │  │
│ └─────────────────────────────────────────┘  │
│ [✏️ 修改文件名]                              │
│                                              │
│ [保存 JSON + 重命名文件]                     │
└─────────────────────────────────────────────┘
```
